# 브랜업 대시보드 입력 품질

> 이 페이지는 **업무를 어떻게 등록하는가**의 문제를 다룬다. 등록된 업무가 **어떻게 종결되는가**(완료/삭제/시리즈 교체)는 [[concepts/브랜업-업무-완료-판별|업무 완료·삭제 판별 규칙]]에서 다룬다.
> 두 축은 분리해야 한다 — 2026-11-04 회차에서 **경과 +11건 중 13건이 입력 사고**였는데, 이를 집행 실패로 읽으면 리포트 전체가 틀어진다.

## 1. 중복 등록 — 같은 업무 12건 (2026-11-04 첫 실측)

11-04 11:59:46~12:07:34 **8분 사이에 동일 제목 12건**이 등록됐다.

| 항목 | 내용 |
|------|------|
| 제목 | `[칸겐뷰트] 종이 쇼핑백 규제 리서치 2차 (미국/캐나다)` (전건 동일) |
| 담당·마감 | 전경표 · 전건 **2026-11-04** |
| 레코드 | `#595`~`#606` (id 12개 전부 상이, `display_num`만 다름) |
| summary | `#595`~`#597` = 3단계 진행상황 / `#598`~`#606` = **`ㅇㅇ`** |
| 추정 원인 | 대시보드 저장 버튼 **반복 클릭** 또는 저장 후 응답 지연으로 인한 재전송 |

**영향:** 12건이 전부 경과 집계에 포함돼 **전사 마감 경과가 59 → 70건(+11)** 으로 뛰었다. 같은 날 다른 유입은 2건뿐이었으므로, 이 수치는 **업무 지연이 아니라 계수 오염**이다.

**정리 규칙:**
1. 같은 제목 + 같은 담당 + 같은 마감 + 생성 시각 5분 이내 = **중복 후보**로 묶는다.
2. summary가 가장 충실한 1건(여기서는 `#595`)만 남기고 나머지를 삭제한다.
3. 삭제 후 경과가 −11 되는데, **이를 '개선'으로 로그에 적지 말고 '착시 정정'으로 적는다.**
4. 중복은 완료 이력을 남기지 않으므로 [[concepts/브랜업-업무-완료-판별|판별 규칙]]상 '하드 삭제'로 분류된다 → **하드 삭제 건수를 오염시키지 않도록 '중복 정리'를 별도 사유로 표기**한다.

**예방:** 현재 대시보드에는 중복 등록 방지 장치가 없다. `[대시보드] 업무 상태변경 시 텔레그램/카카오톡 알림`(#572, 이향석, 11-06)과 같은 라인의 **입력 검증 기능**(동일 제목 최근 N분 내 존재 시 경고)이 필요하다.

## 2. '등록 즉시 경과'가 아니라 '등록 당일 마감'이다 — 용어 정정

위키는 10-28 이후 이 패턴을 **'등록 즉시 경과'**로 적어 왔으나, 실측하면 정확한 표현은 **'등록 당일 마감(D-0 등록)'** 이다. 등록 시점에는 마감이 유효하고, **다음 날 0시에 전건 경과로 편입**된다.

| 등록일시 | 업무 | 마감 | 실제 상태 |
|----------|------|------|----------|
| 10-28 17:2x | `[칸겐뷰트] 종이 쇼핑백 규제 리서치 2차`류 선행 2건 | 10-28 | 당일 마감 → 익일 경과 |
| 11-02 15:31 | `태국 상자 인쇄 가능 여부 확인` | 11-02 | 당일 마감 → 5회 경과 후 하드 삭제 |
| 11-03 13:46 | `50ml 미국 캐나다 문안 규정 (전면만)` | 11-03 | 당일 마감 → 익일 1일 지연 완료 |
| 11-04 09:51 | `change your water… 불어 번역 여부` | 11-04 | 당일 마감 → 경과 1일 |
| 11-04 11:59~ | `[칸겐뷰트] … 2차` ×12 | 11-04 | 당일 마감 → 전건 경과 1일 |

- **왜 문제인가:** 등록과 동시에 '오늘 안에 끝내야 하는 일'이 되므로 **익일 리포트에 반드시 경과로 잡힌다**. 게다가 담당자에게는 **착수 시간이 0에 가깝다**(오후 등록 → 당일 마감).
- **규칙 제안:** 등록 시 마감일이 **등록일과 같으면 경고**하고, 최소 **D+1 이상**을 기본값으로 강제한다. 리드타임이 필요한 리서치·발주는 담당자별 기본 리드타임(리서치 3일, 발주 5일)을 자동 제안.

## 3. summary 품질 — `ㅇㅇ`, 제목 반복

- **`ㅇㅇ` 9건**(§1 중복분), `test` 류 등 의미 없는 summary가 그대로 남는다. summary는 위키·리포트가 **유일하게 참조하는 맥락 필드**이므로, 비어 있으면 업무는 제목 한 줄로만 존재하게 된다.
- **제목을 그대로 복사한 summary**도 다수(`이카운트 생산/구매/재고 관리 시스템 구축` = 제목과 동일). 이 경우 진행 상황·산출물 위치를 알 수 없다.
- **규칙:** 위키에 반영할 때 summary가 비어 있거나 3자 이하이면 **`summary 없음`으로 명시**하고, 완료 판정 시 **산출물 문서 존재 여부를 별도로 확인**한다.

## 4. 반복·롤링 업무는 중복이 아니다

`정부지원사업 매주 확인`은 활성 목록에 **4건**(#504 11-11 · #522 11-18 · #559 11-25 · #608 12-02)이 동시에 존재한다. 이는 **4주치 선등록(롤링)** 으로, `series_id`가 같은 정상 상태다.

- **판별:** `series_id`/`series_seq`가 있으면 **반복 업무** → 중복으로 세지 않는다.
- **주의:** 시리즈가 교체될 때 구버전이 목록에서 사라지는 것은 **삭제가 아니다**([[concepts/브랜업-업무-완료-판별|판별 규칙 §8]]). 11-04에는 `[주간업무전략]` 4건이 사라지고 **`[주간업무회의]` 4건(#609~#612)이 신설**됐다 — 시리즈 자체가 바뀐 사례로, **제목이 달라 단순 제목 매칭으로는 교체를 인식할 수 없다**(→ 담당·주기·마감 요일로 대조해야 함).

## 5. 이 페이지를 만든 계기

2026-11-04 하루의 입력을 분해하면:

- 신규 20건 = **중복 12 + 실등록 8**
- 실등록 8 = 문안·포장 2 (`불어 번역 여부`, 중복의 원본 1) + 재무·세무 1 (`세무사 솔루션 분석`) + 운영시스템 1 (`이카운트…구축`) + **시리즈 5** (`[주간업무회의]` 4 + `정부지원사업 매주 확인` 1)
- 즉 **사람이 새로 만든 업무는 4건**이고, 나머지 16건은 중복·자동생성이다.

**결론:** 활성 건수·경과 건수의 **일별 증감을 그대로 업무량으로 읽으면 안 된다.** 매 회차 ① 중복 후보 ② 시리즈 자동생성 ③ 실등록을 **3분류로 먼저 쪼갠 뒤** 증감을 해석해야 한다.
